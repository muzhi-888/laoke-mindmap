# 信息分层与 MECE 原则

导图好不好，80% 取决于"分层对不对"。这一篇讲两个硬标准：层级清晰、不重不漏。

---

## 一、分层的基本功

### 1. 同一层的节点要"同一维度"
错误示范（一层里混了维度）：
```
产品上线计划
  研发        ← 按职能
  预热海报    ← 按动作（和"研发"不同维）
```
正确示范（同一层统一维度）：
```
产品上线计划
  研发
  运营
  风险
```
然后"预热海报"挂在"运营"下面。每一层只回答一个问题：这一层我在按什么切分？

### 2. 子节点必须是父节点的"展开"，不是"平行转移"
错误：父节点"后端接口"，子节点"前端页面"——这俩是兄弟不是父子。
正确：父"研发"→ 子"后端接口 / 前端页面"；父"后端接口"→ 子"鉴权 / 限流"。

### 3. 别跳层
`中心 → 叶子` 中间空着，信息断层。要么补中间层，要么把叶子提上来。

---

## 二、MECE 原则

MECE = Mutually Exclusive, Collectively Exhaustive（相互独立，完全穷尽）。这是麦肯锡式的拆分铁律，做导图拆解时极其好用。

- **相互独立（不重）**：两个分支不该有重叠。写"新用户 / 老用户 / 流失用户"就重叠了（流失用户算老用户吗？）。改成"新用户 / 活跃老用户 / 沉睡用户"边界清晰。
- **完全穷尽（不漏）**：所有分支加起来要覆盖全集。做"风险"分支，至少覆盖：技术 / 业务 / 合规 / 外部。漏掉一块，决策就盲。

### 怎么检验 MECE
问自己两句：
1. 有没有哪两个分支其实是一回事 / 有交集？（查"不重"）
2. 有没有明显该有但没列的分支？（查"不漏"）

### 常用 MECE 切分轴
- 时间：前 / 中 / 后；过去 / 现在 / 未来
- 空间：国内 / 海外；华东 / 华南 / 华北
- 职能：研发 / 运营 / 市场 / 财务
- 程度：高 / 中 / 低；核心 / 边缘
- 流程：获客 / 转化 / 留存 / 变现
- 内外：内部能力 / 外部环境

选一个轴切到底，比每层的轴换来换去清楚得多。

---

## 三、信息分块（chunking）

人一次能记住的"组块"大约 4±1 个。所以：
- 一级分支控制在 3-7 个。
- 单个节点的子节点别超过 7 个，超了就再分组。
- 名字短：一个节点最好 2-6 个字，长句子放叶子或更底层。

---

## 四、给导图上"行动标签"

纯知识导图容易"看了就忘"。加行动维度后价值翻倍：
- 叶子节点挂 `[负责人]` / `[截止]` / `[状态]`
- 或挂 `[待办]` / `[已完成]` / `[风险]`
本 Skill 不强制格式，但建议你在导出的 Markdown / HTML 里手动补这些标签，导图就从"笔记"变成"看板"。

---

## 五、速查

> 每层一维度，父子是展开，不跳层、不重叠、不遗漏。
> 一级 3-7 个，节点短而准，叶子挂行动。
