# 从大纲到导图的转化规则

本 Skill 的 `outline_to_mindmap.py` 把"有层级的文本"变成导图。这篇讲清它认什么格式、怎么算层级、边界怎么处理，方便你写对输入。

---

## 一、支持的输入形态（可混用）

### 形态 A：Markdown 标题
```
# 一级（中心）
## 二级
### 三级
```
`#` 的数量减一就是层级。`#` = 第 0 层（中心），`##` = 第 1 层，以此类推。

### 形态 B：缩进项目符号
```
- 顶层项
  - 子项（缩进 2 空格）
    - 孙项（缩进 4 空格）
```
每多 2 个空格 = 降一层。`-` `*` `+` 都认。

### 形态 C：编号列表
```
1. 顶层项
2. 顶层项
   a. 子项
```
编号不影响层级，只看缩进。

### 形态 D：中文编号
```
一、顶层
  1. 子项
```
也认。

### 形态 E：纯缩进文本（无符号）
```
顶层
  子层
```
只看缩进算层级。

---

## 二、标题与列表混用的关键规则

列表项相对"最近一个标题"再下沉一层。例子：
```
# 产品上线计划        <- 第0层
## 研发               <- 第1层
- 后端接口            <- 相对"研发"(第1层) 再深1 = 第2层
  - 鉴权              <- 第3层
```
所以 `- 后端接口` 会正确挂在"研发"下面，而不是塌回顶层。这是本脚本和"纯按缩进算"的工具最大的不同——更贴近人写文档的直觉。

---

## 三、中心主题怎么定

- 如果输入只有**一个**第 0 层节点（比如只有一个 `# 标题`），它直接当中心。
- 如果有**多个**第 0 层节点（比如并列几个 `#`），脚本自动套一个虚拟中心（默认"中心主题"，可用 `--center` 改），保证导图"只有一个中心"。
- 如果输入是纯列表没有标题，第一层列表项就是一级分支，同样套虚拟中心。

> 经验：写导图前先想清楚"唯一中心"是什么，写一行 `# 中心主题` 开头最稳。

---

## 四、空行与格式

- 空行忽略，不影响层级。
- Tab 自动当 4 个空格处理（所以 Tab 缩进也能用）。
- 节点文字里的特殊字符（括号等）在 Mermaid 输出里会被安全处理，不影响 HTML / Markdown 输出。

---

## 五、常见输入错误

| 错误 | 现象 | 改法 |
|------|------|------|
| 标题和列表缩进没对齐 | 层级错乱 | 列表始终相对最近标题下沉，确认缩进是 2 的倍数 |
| 中心主题写了好几个 `#` | 出现虚拟根 | 只留一个 `#` 当中心 |
| 用 3 空格缩进 | 层级算错（3//2=1） | 用 2 空格或 4 空格，别用 3 |
| 节点名太长 | 导图难看 | 节点短些，细节放子层 |

---

## 六、输出三种产物

1. **Mermaid**：`mindmap` 语法，粘进支持 Mermaid 的编辑器（很多笔记/文档工具内置）即渲染成图。
2. **嵌套 Markdown 列表**：接着在笔记里用，或当文章骨架。
3. **自包含 HTML**：双击打开是可折叠的交互导图，零外部依赖，发给别人也能看。

用法：
```
python outline_to_mindmap.py 输入.md --out all --write
```
`--write` 会把三种产物写成文件，方便分发。
