# 思维导图核心结构与应用场景

思维导图不是"把大纲画花"，是一种**用层级把信息结构化**的思考工具。先搞懂它的骨架，才知道什么时候该用、什么时候不该用。

---

## 一、核心结构

一张标准思维导图只有三样东西：

- **中心主题（Root）**：整张图要回答的一个问题 / 一个主题。有且只有一个。
- **主分支（一级节点）**：从中心直接发散的几个大块，通常 3-7 个。太多说明主题没收敛。
- **子节点（二三级…）**：逐层展开的细节、例子、行动项。

原则：**越靠近中心越抽象，越往外越具体**。中心是"为什么"，叶子是"怎么做 / 是什么"。

---

## 二、什么时候该用思维导图

| 场景 | 适合吗 | 为什么 |
|------|--------|--------|
| 头脑风暴 / 发散想点子 | ✅ 非常适合 | 鼓励多分支、不评判、先广后深 |
| 拆解一个问题（为什么 → 怎么办） | ✅ 适合 | 层级天然匹配"根因→对策" |
| 读书 / 听课做结构化笔记 | ✅ 适合 | 把线性内容还原成知识树 |
| 制定计划（目标→任务→步骤） | ✅ 适合 | 每片叶子可挂负责人/时间 |
| 写长篇线性文章 | ⚠️ 不一定 | 文章是线性的，导图是网状的，导图适合"打骨架"，正文另写 |
| 纯时间排序的一件事 | ❌ 不适合 | 时间线用 timeline 比导图清楚 |
| 两两对比（A vs B） | ❌ 不适合 | 矩阵 / 表格更合适 |

> 一句话：凡是"一个主题散出多个维度、维度还要再细分"的，导图就合适。凡是"顺序 / 对比 / 单一因果链"的，换别的图。

---

## 三、导图 vs 大纲 vs 其他图

- **导图 vs 大纲**：大纲是"读给人看的层级"，导图是"想给人看的网状"。本 Skill 的脚本能双向互转——先用导图发散，再导出 Markdown 大纲去写文档，是最常见的用法。
- **导图 vs 流程图**：流程图讲"先后 / 条件"，导图讲"包含 / 拆解"。别混。
- **导图 vs 矩阵**：矩阵做"二维对比"（重要×紧急、自己×对手），导图做"一维发散"。

---

## 四、常见新手误区

1. **中心主题太大**：写"工作"而不是"本周工作重点"。主题一虚，分支就散。
2. **分支太多**：一级分支超过 7 个，记不住也用不上。合并同类。
3. **叶子太早收**：第一层就写"做一下"，没展开成可执行的子节点。
4. **纯抄书不加工**：把目录原样搬进来不叫导图，叫目录。导图要"用自己的话重新组织"。
5. **为了好看忽略逻辑**：颜色图标是加分项，层级正确才是及格线。

---

## 五、本 Skill 怎么帮你

你给它一份"有层级的文本"（Markdown 标题 / 缩进列表 / 编号列表），它：
1. 解析出层级树；
2. 自动生成三种产物（Mermaid / Markdown 列表 / 自包含 HTML 导图）；
3. 多一级节点时自动套一个"中心主题"根，保证导图有且只有一个中心。

你只需专注"把层级想对"，渲染和分发交给脚本。
